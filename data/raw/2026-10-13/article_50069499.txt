Description jsnell opened on Oct 13, 2026 Issue body actions edit( @lcnr ): given that this issue has been shared online and is currently getting quite a few visitors, here's some additional context ﻿ Rust's type system is intended to prevent memory unsafety. Upholding this promise is something we take very seriously, which is why we've been working on things like the next-generation trait solver , the region constraint rework , and more generally Project Zero . It is a large priority of the Types Team to fix all type system unsoundnesses and to work towards there being a solid foundation to minimize the risk of unknown ones. This bug is a P-high issue and would have been P-critical regardless of whether people encountered it in the wild. The reason that it is "only P-high " is that it's 11 years old. A bug like this which has not been found during the last 11 years cannot actually be that easy to hit. ﻿ Looking at the bug itself, it is also very likely that this unsoundness has not caused memory unsafety by accident. While it looks easy to trigger, to exploit this you need an intentionally malicious Drop implementation.
