Our own EFI loader, our own replacements for Apple's closed drivers, a UEFI port, and a Linux Wi-Fi driver on a compatibility layer make that possible. It runs in two places: POCO X5 Pro 5G (redwood, Snapdragon 778G) — nothing is flashed: the UEFI is started with fastboot boot , the whole system lives in RAM, and after a reboot the phone is back in Android; QEMU ( virt , aarch64) — the same thing on any Linux computer, no phone needed. This repository is half of the project: Repository What hackios-xnu-kernel (this one) XNU patches, the EFI loader, the UEFI port, Wi-Fi, QEMU scripts, xl , prebuilt kernel/loader/UEFI, common/ scripts hackios-xnu-userland our init, injected libraries, launchd jobs, the APFS image builder, the scripts that take iOS out of Apple's IPSW, Metal/Mesa work No Apple files are in either repository. ios165/fetch.sh downloads the iOS 16.5 IPSW from Apple's own CDN to your machine and extracts what is needed there. What works Works Does not work (yet) Lock screen, swipe to unlock, home screen with all icons (two pages), stock iOS 16 wallpapers Cellular, Bluetooth System gestures: swipe up (home, app switcher), edge swipe (back), Control Center Charging under our kernel (the phone only discharges) Apps: Settings, Clock, Calendar, Photos, Notes, Safari and more; widgets (Weather, Calendar) on the phone Metal for apps (in progress: 293 of 456 system shaders already run on the Adreno, see docs/air.md in hackios-xnu-userland) Phone touchscreen (Goodix GT9916), multitouch, wake on touch; real power and volume keys App Store content and Apple ID sign-in (no Secure Enclave; FairPlay daemon exits) Up to 8 CPU cores ( cpus=8 ), big core at 2.4 GHz, ~20 s to the lock screen Video and Live Photo recording Adreno 642L GPU through Mesa/freedreno ( gpu=1 , OpenGL ES for CoreAnimation) Wi-Fi (WCN6750, ath11k): join from Settings, Safari over Wi-Fi, 55–90 Mbit/s Sound (speakers, main microphone), camera in Camera.app (front/rear, preview, focus, HEIC photos) Data that iOS writes survives a reboot ( var_store=1 ufs_write=1 ); iOS root volume on the phone's flash Sileo + Procursus (dpkg, apt), tweaks, SSH It is a research bench, not a ROM: a session lasts a given number of seconds, then the kernel returns to the loader and hands over its log. Quick start: QEMU, no kernel build prebuilt/ holds the kernel, loader and our programs built from these repositories, so all you need is the system image, which is made on your machine from Apple's IPSW. Needs: Linux x86-64, ~12 GB free disk, 4 GB free RAM. Packages (Arch): sudo pacman -S --needed git python 7zip lz4 gcc qemu-system-aarch64 qemu-ui-gtk edk2-aarch64 (Debian/Ubuntu: git python3 7zip liblz4-dev gcc qemu-system-arm qemu-efi-aarch64 ; 7-Zip must be 23 or newer — it reads APFS.) git clone https://github.com/oosexgang/hackios-xnu-kernel.git hackios cd hackios common/setup.sh # brings hackios-xnu-userland into the same tree, checks the host ios165/fetch.sh # downloads 7.4 GB from Apple's CDN and extracts what is needed (5-15 min) common/build.sh qemu-virt # builds the APFS images (and the kernel, if the toolchain is there) common/run.sh qemu-virt # a 20-minute session in a QEMU window The lock screen appears after 2–3 minutes. Mouse with the left button held = finger. Unlock / leave an app: swipe up from the very bottom edge; back: swipe from the left edge. Keys: H home, L lock/power, ↑ / ↓ volume, F11 (hold) five fingers. From a script: qemu/touch.py swipe 0.5 0.985 0.5 0.3 250 , qemu/touch.py tap 0.615 0.71 , qemu/touch.py key home ; screenshot: qemu/screendump.sh shot.png . Right after SpringBoard appears the system is still registering apps: give it 30–40 s. Debian/Ubuntu UEFI firmware: QEMU_EFI=/usr/share/AAVMF/AAVMF_CODE.fd QEMU_VARS=/usr/share/AAVMF/AAVMF_VARS.fd . On the phone (POCO X5 Pro 5G) You need a POCO X5 Pro 5G (redwood) with an unlocked bootloader, adb and fastboot , and the images from the section above. Nothing is written to the phone's storage. The phone's own firmware is not in the repository and cannot be: it is the vendor's and is taken from the very phone it will run on, from its Android: adb pull /vendor/firmware/a660_{gmu.bin,sqe.fw,zap.mdt,zap.b00,zap.b01,zap.b02} fw-gpu/ # GPU (gpu=1) adb pull /vendor/firmware_mnt/image/wpss.{mdt,b02,b03,b04,b05,b06,b07} fw-wifi/ # Wi-Fi (wifi=1) adb pull /vendor/firmware_mnt/image/adsp.{mdt,b02,...,b36} fw-audio/ # sound (adsp=1) adb pull /vendor/firmware/aw8697_haptic.bin fw-haptic/ # haptics (Put the fw-* directories next to the workspace. Wi-Fi also needs fw-wifi/mac — the radio's address on one line — and fw-wifi/network — network name and password. userland/build.sh prints which firmware went in.) common/build.sh redwood GL=1 # images + out/redwood-boot.img common/run.sh redwood 900 # loader into RAM, system image into RAM, a 15-minute session or step by step with xl : ./xl enter # Android -&gt; fastboot -&gt; our loader in RAM (fastboot boot); it brings up its own USB link ./xl ramdisk # upload the system image into the phone's RAM (2.5 GB, ~80 s), once per loader session XL_SECS=900 XL_CMDLINE= " touchscreen=1 cpufreq=1 bootcpu=7 cpus=8 gpu=1 wifi=1 adsp=1 " ./xl run ./xl screenshot shot.png ./xl reboot # back to Android ./xl with no arguments lists every command (logs, screen and sound recording, camera frames, stop, state...). Prebuilt boot image Every release has hackios-redwood-boot.img attached: the redwood UEFI with our loader inside, ready for fastboot boot . It contains no Apple files; the system image is still made on your machine (above). Building from source common/build.sh &lt;device&gt; runs every step that this machine can run and uses prebuilt/ for the rest. Kernel — needs theos in ~/theos (cctools and iPhoneOS16.5.sdk ) and clang lld python perl . Details: xnu/README.md . xnu/apply.sh &amp;&amp; xnu-deps/setup.sh &amp;&amp; ./xnu-build.sh -j8 -k Loader — xnuloader/build.sh (clang + lld-link, an EFI application without EDK2). Images — REST=1 userland/build.sh (variables documented at the top of that file). UEFI — uefi/README.md (Project Silicium port); not needed to run, prebuilt/uefi has it. After rebuilding: tools/update-prebuilt.sh refreshes prebuilt/ . Porting to another device common/new-device.sh &lt; codename &gt; path/to/device.dtb # profile + loader platform from the phone's device tree Then follow docs/PORTING.md : the UEFI port, the loader's platform description, the kernel's drivers, the firmware. Device profiles live in common/devices/ ( redwood.conf , qemu-virt.conf , _template.conf ). How it works fastboot boot ──► UEFI (Mu-Silicium) ──► xnuloader (EFI application) │ stays resident: USB link (fastboot protocol), │ watchdog, receives the kernel's log ▼ XNU (BCM2837 config as the base + our platform) ├─ GICv3, timer, video console, return to the loader ├─ APFS (images in RAM, iOS volume on flash), ramfs (/private/var, /tmp) ├─ minicrypto instead of corecrypto, AMFI and Sandbox stand-ins (MAC policies) ├─ driver replacements: IOSurface, IOMobileFramebuffer, AppleKeyStore, network stack ├─ input: /dev/redwood-touch ◄─ Goodix GT9916 (phone) / virtio-input (QEMU) ├─ GPU: Adreno 642L, Wi-Fi: WCN6750 (ath11k via LinuxKPI), sound: ADSP / virtio-sound ▼ iOS 16.5 launchd → logd, notifyd, cfprefsd, runningboardd, backboardd, SpringBoard, apps ├─ our libraries are injected into backboardd, SpringBoard and mediaserverd │ (virtual HID services, a few ObjC method swaps — in memory only) └─ mediaserverd gets our CoreAudio output device (RedwoodAudio.driver) The iOS programs, frameworks and dyld shared cache are not changed by a single byte: what they miss is done by the kernel (driver replacements) or by a library the kernel injects with DYLD_INSERT_LIBRARIES ( kern.exec_inject ).
