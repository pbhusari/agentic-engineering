What BUI is BUI takes the user interface of Blender (its widget drawing, its interaction rules and its look) and turns it into a standalone UI library with a small C core. Your code builds the widget tree and handles callbacks. Layout, input, drawing and presenting all happen in fast native code, on the CPU or the GPU. At the heart of BUI is the kit : a small runtime written in C. The kit holds every widget in one tree, lays them out, handles the mouse and keyboard, and draws them the way Blender does. The drawing code is a C port of Blender's own widget code, and the interaction follows Blender's rules. On top of the kit sit bindings : thin layers that let Python, Rust, JavaScript, C++ and Dear ImGui talk to it. What BUI is not: Not Blender. It contains the parts of Blender's UI code it needs and builds on its own. You don't need Blender installed, and you don't need to know Blender to use it. Not a browser. The Rust and JavaScript sides use HTML and CSS as a UI language , but there's no browser engine, no webview and no network. Not a re-imagining. The widget drawing is ported from Blender's interface_widgets.cc , and the Dear ImGui support runs the real Dear ImGui. 2. Why BUI exists Blender's interface is famous for how it feels . You press a number field and drag: the cursor vanishes, the value glides under your hand, and you never hit the edge of the screen. You type 2*pi into a field and it just works. You type "ad cu" into a menu and it finds "Add Cube". Millions of artists have these habits in their hands. That interface is also fast and frugal. It redraws only what changed, sleeps when nothing does, and starts in milliseconds. BUI exists so that any app, in any language, can have both: Blender's feel, and Blender's efficiency. 3. Who it's for You have a tkinter app and wish it looked less like 1998. Run it on BUI, unchanged. You're building a tool for artists who already know Blender. Give them the panels, sliders and shortcuts their hands expect. You write Rust or React and want a native desktop UI without shipping a browser. You use Dear ImGui and want it to look and feel like Blender, with one build flag. You're curious how a UI toolkit works. The source is readable, and the concepts are explained in plain words. 4. Features at a glance Blender's widgets and interactions Number fields you drag with a hidden, continuous cursor : Shift for precision, Ctrl to snap. Math in number fields , with Blender's own expression evaluator: 2*pi , min(4, 3) , round(1.7) , x if c else y . Ctrl+Wheel steps values, Ctrl+C / Ctrl+V copy values, Backspace resets. Drag across checkboxes to set them all. Press-drag-release menus, pie menus, and Blender's fuzzy menu search : "ad cu" finds "Add Cube", typos are forgiven, recent picks rank first. Ctrl+Z / Ctrl+Shift+Z on every UI edit, and inside a text field while you type; Tab between fields. Blender's float display precision, multi-field vertical drags, and panels that collapse with Blender's animation. The HSV color wheel, color ramps, curves, trees, lists, text areas, canvases, a node editor and Blender's File Browser. Blender's Dark and Light themes , switchable at run time. Python, four ways tkinter : all 7,846 public names of tkinter and ttk. Nine real programs behave identically on the standard library and on BUI. Qt syntax : widgets, layouts, signals, QPainter , menus and timers. Components : 45 Blender widgets, editors and templates. Dear ImGui : from blenderui import imgui , pyimgui-style. One pip install , no Qt or Tk widgets drawing anything. Rust: the web platform, natively All 113 HTML elements , drawn like a browser draws them; styled gives any subtree Blender's look, and Blender components ( &lt;NumberSlider&gt; , &lt;Button&gt; , &lt;ColorSwatch&gt; ...) are real Blender widgets. Modern CSS : flexbox, grid with named areas, tables, calc() and every math function, var() , oklch() and color-mix() , :has() , nesting, @layer , @media ranges, @container , ::before / ::after , counters. Effects and motion : @keyframes animations and transitions, filters, backdrop-filter , blend modes, clip-path , masks, 2D transforms, border-image . Tailwind CSS v4 : class="md:hover:bg-sky-500/50" or bare attributes ( &lt;div p-4 bg-[#4772b3]&gt; ), with "did you mean" compile errors . rsx! / view! HTML-like markup, #[component] , and hooks in zopra, React or Leptos style ( use_state , signal , Memo , Effect , context). gpui-compatible syntax too: div().flex().gap_2() , Render , cx.listener . On crates.io : cargo add blenderui . Fast by design Damage rendering : an idle UI costs 0% CPU, and a hover redraws only the widget it touches. Opt-in GPU renderer (Direct3D 11 on Windows, OpenGL 3.3 on Linux), modeled on Blender's instanced widget drawing. It draws the same pixels as the CPU raster. In the benchmark, 2–4× less CPU per frame than gpui-fast , with less RAM and a ~5 ms first frame . Blender's text : Inter (Blender's UI font) is embedded and rendered with FreeType the way Blender renders it, so text looks the same on every platform. On the GPU, glyphs are drawn from their outlines with Slug , falling back to a per-glyph atlas like Blender's. Images One decoder set for every language , in C: PNG, GIF, BMP, TGA, QOI ( Wuffs , memory-safe), JPEG (libjpeg-turbo), WebP including animated (libwebp), Radiance HDR, PNM and SVG. The design is Blender's imbuf: one image type and a format table. Decoded at the size it is drawn, off the UI thread : JPEG thumbnails use DCT scaling (a 4K photo becomes a 256 px thumbnail in ~12 ms), visible images first, scrolled-away requests cancelled, and only the image's rectangle redraws when it arrives. The page never jumps: sizes come from the file header. One memory-budgeted cache (256 MiB by default). Scrolling 1,000 photo thumbnails: 2.9 ms p99 frames and 100 MB , against 96 ms and 2.5 GB when decoding on the UI thread; 0 allocations in a settled frame, every block freed at exit. Images . Animated GIF and WebP play everywhere an image shows, decoded one frame at a time at the size drawn (two frames held per animation), each frame for its own delay, only the image's rectangle repainting. Off screen, scrolled away or in a hidden window they pause: 200 animations at once take 0.76 ms p50 / 1.5 ms p99 render frames, and nothing at all once off screen. frame holds one frame; reduced motion holds them all. Large images on the GPU : images over 2047 px get a texture of their own on Direct3D 11 and OpenGL (tiled only past the device limit), freed with the image. Video : &lt;video&gt; in every language, decoded by the OS (Media Foundation with DXVA, GStreamer, AVFoundation; loaded at run time) at the size drawn, frames in one GPU texture per player updated in place, YCbCr converted in the shader, and nothing decoded off screen . 1080p plays at 0.99 ms render frames and 9 % of a core on the GPU renderer, five at once at 28 %, with 0 allocations per frame . Play, pause, seek, rate, loop, poster, state events, and Blender-style controls. Video . &lt;img&gt; , CSS background-image , object-fit , Blender Image components, tkinter PhotoImage (now also JPEG, WebP, BMP, TGA, QOI, HDR, SVG), canvas items, data-table image columns, chat-list media and Dear ImGui textures (animated ones too). JavaScript and React React 19.3 renders to BUI: HTML host components, CSS and Tailwind, events, Suspense, transitions, actions, and Blender components ( &lt;NumberSlider&gt; , &lt;Button&gt; ...). BUI draws them, on the CPU or the GPU; there's no browser and no webview. React's hooks, by React's names , holding signals: pass one into JSX ( {count} ) and a change updates that one node without re-rendering; read it while rendering ( count.value ) and the component re-renders, as with React. A conformance suite checks each hook against React's own. Svelte 5 ( @blender-ui/svelte ): components with runes, snippets, bindings and scoped styles, mounted into native windows; Svelte's compiled code runs on BUI's DOM, so a $state change updates the one node that shows it. @blender-ui/native : a DOM-like API ( createElement , appendChild , addEventListener ) with the same signals, for apps without a framework, and the shared layer the React and Svelte bindings are thin adapters over. Node.js and Bun , through a napi-rs addon, with headless mode for tests. Small standalone apps bui build app.jsx produces one executable of 6.3 to 6.9 MB (by the features it uses): BUI with an embedded QuickJS engine. First frame in ~70 ms , at 19 MB of RAM, with nothing to install. There's no browser and no webview. --bun builds a Bun executable instead, with Node's APIs and a JIT. Builds take under a second: the app's bundle is appended to a prebuilt runtime. Pay for what you use : one feature table ( features.json ) drives CMake options, cargo features and bui build , which links the smallest runtime an app needs: 6.3 MB for hello world, 6.9 MB with images or video. Binary size . Dear ImGui The real Dear ImGui 1.93 : every function of imgui.h works, including ShowDemoWindow() . Four languages : C++ (drop-in imgui.h ), C ( cimgui.h , all 399 functions), Python and Rust (generated from imgui.h ). Blender's look : Blender's theme colors and metrics with Inter; or, with BUI_IMGUI_BLENDER_WIDGETS=ON , Blender's actual widgets and interaction, pixel-identical to BUI's own. Idle costs nothing : frames run only on input and while something animates. Native everywhere Native windows on Windows (Win32) and Linux (X11, Wayland through XWayland), and an experimental Cocoa host for macOS ported from Blender's GHOST. HiDPI : per-monitor DPI on Windows, Xft.dpi on Linux, Retina on macOS. Headless mode for tests and screenshots, with a virtual clock that steps animations exactly. On Linux, libX11 and libGL are loaded at run time, so BUI imports on servers without them. 6. A gallery Every screenshot here is a real BUI window, rendered off-screen. Install Python. You need CPython 3.11 or newer. Wheels are published for Windows, Linux and macOS, so there's nothing to compile. One package gives you all four Python APIs (tkinter syntax, Qt syntax, the Blender components and Dear ImGui): pip install blenderui python -c " import blenderui; print(blenderui.__version__) " Import it as blenderui . You'll also see import bui in older examples: it's the same code under its original name, but an unrelated project owns bui on PyPI, so prefer blenderui in anything you publish. Rust. The crate is blenderui on crates.io : cargo add blenderui The first build compiles BUI's C kit for you, so you need Rust 1.88 or newer, CMake and a C compiler (on Windows, the Visual Studio Build Tools for the default MSVC target), and on Linux the X11 headers ( libx11-dev or libX11-devel ; no GL headers are needed). JavaScript. You need Node.js 18 or newer, or Bun: npm install @blender-ui/react react # or: bun add @blender-ui/react react npm install @blender-ui/svelte svelte # Svelte 5 npm install @blender-ui/native # the DOM-like API, without React The npm packages are prebuilt for Windows x64 . On Linux , build the addon from a clone ( npm install then npm run build in bindings/ , with Rust, CMake and a C compiler); windows are native X11 windows there. On macOS , JavaScript runs headless for now (see Platforms ). C and C++. Build from source with CMake 3.20+ and a C11 / C++20 compiler (MSVC, GCC or MinGW-w64, or Clang); on Linux, also the X11 headers: git clone https://github.com/ppmpreetham/BUI &amp;&amp; cd BUI cmake -S . -B build cmake --build build -j 2 ctest --test-dir build # optional: run the test suites In your own CMake project, add BUI as a subdirectory and link bui::kit (or bui::imgui for Dear ImGui): add_subdirectory ( BUI ) target_link_libraries ( myapp PRIVATE bui::kit ) Dear ImGui. Python gets it with pip install blenderui ( import blenderui.imgui ). C++ links bui::imgui , C links bui_cimgui . Rust uses the blenderui-imgui crate: cargo add blenderui-imgui If something goes wrong: Symptom Fix ImportError: buipy You're running from a source checkout without a build. Build first ( cmake --build build ), or set BUIPY_BUILD_DIR . The extension must match your Python version. The window never appears Start the event loop: mainloop() , app.exec() or App.run() . Blurry or tiny UI Set BUI_UI_SCALE , for example BUI_UI_SCALE=1.25 . gpu=True does nothing Run with BUI_GPU_DEBUG=1 to see why the GPU device didn't start.
