TV boxes, old tablets, single-board computers and routers all have a CPU, some RAM and flash storage that sit idle most of the day. smolmaxxing finds the biggest model each of them can really run, then pushes it further with custom kernels, careful memory use and weights streamed from flash. Every number in this repo was measured on the device itself. Three devices so far 📺 Xiaomi TV Box S (3rd Gen) 📱 iPad Air (2013) 📞 OnePlus Nord CE 2 (2022) Chip Amlogic S7D, 4× Cortex-A55 Apple A7, 2 cores MediaTek Dimensity 900, 2× Cortex-A78 + 6× A55 RAM 1.9 GB (about 1 GB usable) 1 GB (about 700 MB usable) 7.4 GB (about 3 GB free) OS Android 14, no root iOS 12.5.7, jailbroken Android 13, no root Everyday model Qwen3.5-2B at 7.7 tok/s Bonsai-1.7B (1-bit) at 24-26 tok/s Qwen3.6-35B-A3B at 4.9-5.7 tok/s Biggest model Ling-mini-2.0, 16B, at 5.1 tok/s Ling-mini-2.0, 16B, at 2.6-4.5 tok/s Qwen3-Next-80B-A3B at 2.8-3.2 tok/s Full results docs/tv-box.md ipad-air/README.md docs/phone.md The TV box and the iPad run 8B and 16B mixture-of-experts models on about 1 GB of RAM, and the phone runs 35B and 80B ones with about 3 GB free. They all keep only part of each model in memory and read the rest from flash as it's needed. More devices (single-board computers, routers, more phones) are coming. The techniques aren't tied to one box: the 1-bit kernel needs only basic NEON, and the flash streaming works on any Linux or Android device with more model than RAM. Got a small device? Run a model on it and submit your numbers : we'll add them to the results. How it works All of it is a patch on llama.cpp . The main ideas: Kernels built for the chip. A 1-bit lookup-table kernel, repacked 2-bit and ternary formats for the Cortex-A55, and versions of them for the A7, which has no dot-product instructions. Less RAM per model. Most of a small model's vocabulary is rarely used, so we drop those output rows. On the TV, a "headless" mode also stops the launcher and Google services while a model runs. Experts paged from flash. A mixture-of-experts model only uses a few experts per token. We keep the popular ones in RAM, read the others from flash on demand and prefetch the next layer's. This is how 8B and 16B models run on 1 GB, and 35B and 80B models on a phone. Streaming for dense models bigger than RAM, at the flash's full speed. docs/how-it-works.md has every technique with its measured gain. Try it The quickest start is a ready-made model file from Hugging Face. They need the patched llama.cpp: stock llama.cpp can't load them.
