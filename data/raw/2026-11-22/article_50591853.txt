files Repository files navigation README MIT license More items LookAtMyQuant LookAtMyQuant is a quantization compiler. It measures how much each stored piece of a model hurts the output when compressed. It then picks a code for each piece so the whole model fits a size budget with the least damage. On Gemma 4 E2B, its GGUF has 12× lower KL than Q4_K_M at the same file size. The method and every result are on the site . The code is under the MIT license. LookAtMyQuant 2: Qwen3.5-4B in 1.2 GB LookAtMyQuant 2 takes Qwen3.5-4B to 1.23 GB, 2.3 bits per weight. The file solves 330 of 540 exact-answer math problems. Prism ML's Bonsai 2 Ternary 4B solves 328 at 1.20 GB, and the original solves 359. Its KL from the original on held-out text is 0.45 nats, against 0.59 for Bonsai. The recipe is post-training quantization with trellis codes, calibrated on the model's own worked math solutions with digit tokens weighted 10×, and with bits allocated per row by Fisher information. 4,000 steps of distillation follow, in which every layer is re-quantized once from the original weights. The page has the findings, the full recipe and its cost, about $34 of GPU time. The recipe's code is here, and the next section runs it. The 1.23 GB file itself is the lm2-qwen35-4b-1.2gb release , packed for the Apple Silicon runtime. Qwen3.8-27B in 7.2 GB The same recipe takes Qwen3.8-27B from 53.7 GB to 7.2 GB, 2.1 bits per weight, calibrated and distilled on English prose and chat, code and math. The file solves 401 of the 540 math problems, as many as the original, and Unsloth's UD-IQ2_XXS GGUF of the same size solves 348. It also scores above that GGUF on HumanEval (73.8% against 67.1%), MMLU (78.8% against 75.0%) and GSM8K (94.5% against 92.7%). Beside it sits a 4-bit DSpine drafter (1.02 GB, converted from tencent/Qwen3.8-27B-DSpine-b16 with runtime_mlx/convert_dspine.py and packed with pack_drafter.py ), which roughly doubles decode speed on math and code on Apple silicon. Inkling-2-Mini in 3.9 GB, 4.7 GB, 5.4 GB, 8.9 GB, 11.2 GB, and 12.8 GB Extended to a 26.4B physical / 5.4B active 3×-looped MoE ( L6–17 looped 3× = 48 logical visits, 128 experts top-8), the compiler and full-MoE proximal fine-tuning ( SQYFR / SQYFR v2 / SQYFR v3 ) compress thinkingmachines/Inkling-2-Mini from 18.89 GB of text weights into six Apple Silicon MLX builds spanning 8 GB iPhones up to lossless teacher parity: 3.85 GB ( 1.18 bpp ) , 4.72 GB ( 1.45 bpp ) , 5.38 GB ( 1.65 bpp ) , 8.87 GB ( 2.72 bpp ) , 11.18 GB ( 3.43 bpp ) , and 12.76 GB ( 3.92 bpp ) — combining 4 KB SRAM hashed block-vector trellis codes ( ht2 / ht3 ), row trellis codes ( rtr1 / rtr4 ), surgical 128 -row-group Fisher outlier allocation ( gu_rg_map / dn_rg_map ), dedicated attention projection floors, a tr2 floor on the tail lm_head bucket ( head.7 ), and exact native NVFP4 passthrough ( 69/192 and 109/192 highest-sensitivity expert buckets kept at 0.0 error in the 11.2 GB and 12.8 GB builds). This compresses one piece at a time, leaves the rest exact, and records the KL to the original model. The full set for this model, 2,312 measurements, took about 50 minutes on an L40S. python compiler.py measure --model HuggingFaceTB/SmolLM2-360M --part linear --layers 0-3 --out results/batch/my_measurements.json Allocate. This picks one code per piece, with the least summed KL inside the budget. It needs no GPU. This command uses the SmolLM2-360M measurements in this repository, with a budget of 3.044 bits per weight. python compiler.py allocate --sens ' results/batch/ccSens*.json ' --target disk --items linear --bits 3.044 --out results/compiler/plans/my_plan.json The plan it writes has the same widths as results/compiler/plans/sm_lin_3044.json . Build and score. This quantizes the model to the plan, one matrix at a time. The row plan. lm2Build reads results/compiler/rows/q35_rowplan_1p2GB.json , which gives 1 to 4 bits to each of 1,520 row groups. row_allocation.py made it. Its build-control command builds and packs a control with a fixed split of rows, prepare-rows allocates rows inside the control's packed bytes with rowgroup_alloc.py , and build-rows builds under the plan and checks the packed size against it. The codebooks. The four e-means codebooks the build decodes with are in cache/codes/ . --trellis-fit lloyd gives the earlier ones, and a plan made before the change keeps them unless the flag says otherwise. Recent equal-byte recipe improvements. Two zero-byte additions are available in the compiler and fine-tuning scripts: Softmax-Fisher token table ranking ( --embed-order sfisher-mix in compiler.py measure and quantize.py ). Ranks tied embedding/output buckets by a 50/50 blend of output Softmax-Fisher E[p_v (1 - p_v)] and corpus frequency (and untied output heads by Softmax-Fisher alone). Mid-training equal-byte row reallocation ( --realloc-at 1000 in finetune.py ). Paired with --rebuild-at 1000 , measures each layer's continuous-vs-stored proximal KL gap KL(all P) - KL(layer = W) to shift bits toward deep unabsorbed layers while keeping exact file size ( --realloc-max-delta 1 ). Combined with sfisher-mix on Qwen3.5-4B at identical 1.23 GB ( 2.297 bpp ), WikiText-2 KL fell from 0.425 to 0.387 (−9.0%) and 13-source KL from 0.447 to 0.378 (−15.5%, improving all 13 sources).
