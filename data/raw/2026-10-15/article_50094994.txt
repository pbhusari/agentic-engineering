This happens auto mat i cally but you can also trigger it man u ally - even with a dif fer ent model. It lets you do things like “spawn a back ground fable sub agent to review this code” while you keep prompt ing. Second, we've added back ground shell com mands. If any fore ground shell command or sub agent takes longer than you expect, you can hit a hotkey to move them to the back ground so you can keep prompt ing. Plugins Although OpenCode 1.0 had a plugin system, it never got the atten tion it needed. To correct that, we forced our selves to imple ment nearly every OpenCode 2.0 feature as an inter nal plugin and there are now 80+ of them. This guar an tees that the Plugin API stays well main tained. We've also pro moted TUI plugins from exper i men tal to stable. Since it is all powered by OpenTUI, you can build nearly any thing. Here is an example of some thing useless. We also spent quite a lot of time ensuring everything in OpenCode 2.0 can be hot-reloaded. So it can write a plugin for itself mid-session and use it right away - we covered the design of this in a previous blogpost . You can ask OpenCode to build whatever plugin you want and it knows how to. But if you do want to read the docs, they are available here . The SDK OpenCode can also now be used as a library with the @opencode/sdk package. This is the exact same code that powers our CLI. This means you can strip it down and make your own flavor of OpenCode that runs on a server or in spe cial ized envi ron ments like Durable Objects. And then you can connect to it from any OpenCode client since it speaks the stan dard OpenCode server pro to col. It also has an optional Effect-based API. This one is still in development as things are shifting but you can already use it . Upgrading To upgrade the CLI, make sure you're on the latest 1.x release, then run opencode upgrade --major . To upgrade your desktop app, download the latest here .
