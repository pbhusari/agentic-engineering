The recall worsens as the number of memories grows. Large language models today can recall obscure facts from every corner of the world. Most recently, I was running late for a friend&rsquo;s board game night, so I asked Astra to remind me the rules to Dune: Imperium. It gladly narrated them to me as I drove over and helped me remember the rules well enough for me to play again. We&rsquo;re so used to asking models about anything that we take their vast knowledge for granted. How do models remember so much information? And how much can they store? In this post, I&rsquo;ll go through an intuitive way to look at linear maps, MLPs, and self-attention as different kinds of memory stores. From this intuition we can derive some heuristics for how much memory each layer can store. The key property that characterizes a &ldquo;good&rdquo; memory store is its ability to recall what it stored. After all, even if we could store infinitely many facts, it&rsquo;s not very helpful if we can&rsquo;t recall them when we need to. The more memories we store, the more they interfere with each other when we try to recall one. So throughout the post we&rsquo;ll focus on one quantity, the interference-to-signal ratio, which measures how much the other memories get in the way during recall. The number of memories a store can hold before the interference grows as large as the signal is its capacity . We&rsquo;ll develop this perspective and show how you can go from a linear layer to something better, an MLP, which improves both capacity and recall, and then all the way to self-attention, which has very good recall and can store a potentially unbounded number of memories. With 64-dimensional keys, that&rsquo;s a jump from about 64 memories, to about 2,700, to over a million. Here are the terms we&rsquo;ll use throughout. A memory store is a function $f$ that holds $M$ memories, for $i = 1, \ldots, M$. A memory is one key-value pair: a key $k_i \in \reals^{d_k}$, used for lookup based on similarity, and a value $v_i \in \reals^{d_v}$, which is what we want to retrieve. To use $f$, we query it with an input $x$, and it recalls an output $f(x)$. A good memory store recalls $v_i$ when we query it with $k_i$, or with another vector similar to $k_i$. In the literature, a memory store that recalls by similarity is called an associative memory . An outer product memory store # The most basic memory store is linear: it simply accumulates memories via outer products, $$W = \sum_{i=1}^{M} v_i k_i\transpose = V\transpose K$$ where the rows of $K \in \reals^{M\times d_k}$ and $V \in \reals^{M\times d_v}$ are the keys $k_i\transpose$ and the values $v_i\transpose$. 1 To store a new memory $(k, v)$, we simply add $vk\transpose$ to the existing weights. 2 Aside: a gradient descent step writes a memory Take a linear layer $y = Wx$ inside a network with a scalar loss $L$, and let $\bar y = \grad L(y)$ be the gradient of the loss with respect to the layer&rsquo;s output. The gradient with respect to $W$ is $\bar y x\transpose$, so a step with learning rate $\eta$ is $$W \leftarrow W - \eta\, \bar y x\transpose.$$ This recurrence is a memory update: it updates the weights with a new memory with key $x$ and value $-\eta\bar y$. For more on this view, see Irie, Csordás & Schmidhuber , who express a linear layer trained by gradient descent as attention over all of its training inputs. To query the memory store with an input $x$, we multiply the input by the matrix: $$f(x) = V\transpose K x = \sum_{i=1}^{M} v_i\,(k_i\transpose x).$$ So recall is a lookup by similarity to the stored keys: we compare the query with every key, and return the sum of the values weighted by those similarities. Recall picks up interference # So storing memories is easy: just keep adding outer products to the weights. But what happens when we try to recall one? Let&rsquo;s assume for simplicity that every key is normalized to have length 1, i.e. $k_j\transpose k_j = 1$. Then $$f(k_j) = \underbrace{v_j}_{\text{signal}} + \underbrace{\sum_{i\neq j} v_i\,(k_i\transpose k_j)}_{\text{interference}},$$ meaning we get back the value of the target memory , the one whose key we queried with, plus interference from every other memory whose key is similar to the query. If the keys were all orthonormal, the interference would be zero and recall would be exact. But $\reals^{d_k}$ only has $d_k$ orthogonal directions, so we cannot get perfect recall once we store more memories than the key dimension: $M > d_k$. What is the outer-product store&rsquo;s capacity? Here&rsquo;s an intuitive argument. There are $M-1$ interference terms. If the keys are random unit vectors, each similarity $k_i\transpose k_j$ is about $\pm 1/\sqrt{d_k}$. If the values are random too, with similar lengths, the $M-1$ interference terms add up like a random walk, so the interference&rsquo;s squared length is about $(M-1)/d_k$ times the signal&rsquo;s, and $$\frac{\norm{\text{interference}}}{\norm{\text{signal}}} \sim \sqrt{\frac{M}{d_k}}.$$ Setting this ratio to 1 gives a capacity of $$M \approx d_k,$$ once we store as many memories as the key dimension, the interference is as large as the signal, drowning it out.
