On November 16th, details about a remote memory corruption called NoisyTCP (CVE-2026-99288) in the Linux kernel's TCP stack were published: https://www.openwall.com/lists/oss-security/2026/11/15/2 Today, nine days later, Ubuntu still has not published a fix yet: https://ubuntu.com/security/CVE-2026-99288 Other distros had a fix already available when the details were published. Likewise, a KVM host escape (CVE-2026-99312) affecting AMD virtualization published on Nov 18th has no fix yet either [3]: https://ubuntu.com/security/CVE-2026-99312 Ubuntu has been slow in patching another remote TCP corruption (CVE-2026-98432) lately, where it took multiple weeks until a fix was available. See also: https://chalmovsky.com/posts/wtf-ubuntu Recent news indicates that this is might be exploited in the wild: https://www.greynoise.io/blog/check-point-security-management-servers-intrusion-campaign I think everyone understands that these times aren't easy for security teams. Nevertheless, remote corruption vulnerabilities in the Linux kernel are the kind of thing where I expect updates to be available within hours, not days or weeks. On a recent Ubuntu LTS system, the kernel version is 7.0.0-44. This seems to indicate that Ubuntu is not relying on longterm supported kernels from kernel.org, but is instead backporting patches to an old kernel version. On a Debian stable system, the kernel version is 6.12.118+deb13, indicating that it's based on a very recent longterm kernel from kernel.org. I would consider the backporting strategy for the kernel to be hardly viable and probably everyone should base their Linux kernels on longterm releases supported by the Linux kernel developers. -- Hanno Böck - Independent security researcher https://itsec.hboeck.de/ https://badkeys.info/ Powered by blists - more mailing lists Please check out the Open Source Software Security Wiki , which is counterpart to this mailing list .
