Ghostty 1.4.0 is a major release that includes large performance and memory improvements, a 100% complete Kitty graphics implementation including animation and relative placements (the first non-Kitty terminal to do so), SSH integration improvements, and hundreds more improvements and fixes across all platforms. This release features 7 months of work with changes from 172 contributors over 2,889 commits . Thank you to all the contributors, maintainers, community moderators, translators, packagers, and users who each helped make this release possible. These release notes are painstakingly and lovingly hand-crafted by human Ghostty maintainers, including the full changelog. They take a combined 16+ hours to write, so please enjoy. 🥰 Ghostty is non-profit! Please support development. Almost all donations go directly to paying contributors. Kitty Graphics Animation and Relative Placements PRs: #13943 #13939 #13935 #13934 #13893 #13933 #13389 #13270 #13281 Ghostty now supports Kitty graphics animation and relative placements . These were the last major features of the Kitty graphics protocol that Ghostty didn&#x27;t support. Programs that display animated images with the Kitty protocol, such as an animated GIF shown with kitten icat , now animate in Ghostty instead of showing a single still frame. Frame transmission, composition, and playback control are all supported, and animations pause while the terminal isn&#x27;t visible. Relative placements let a program position one image relative to another image&#x27;s placement, so the child image moves along with its parent. We also did a full conformance pass against the specification and Kitty itself, fixing dozens of behavioral differences. For example, images now scroll with text inside scroll regions ( #4323 ), retransmitting an image ID replaces the old image ( #6711 ), and invalid image data now gets an error response instead of silence, which could leave clients hanging. The full list is in the terminal capabilities section. Kitty graphics are faster, too. Image payloads are now parsed in bulk with SIMD instead of one byte at a time, making large image transfers about 16x faster to parse in our benchmarks (64 MiB of image data, x86_64 Linux), and drawing images costs much less per frame. Our Kitty graphics implementation now covers 100% of the published specification, making Ghostty (and libghostty) the first terminal to do this outside of Kitty itself. Scrollback Compression and Lower Memory Usage PRs: #13264 #13473 #13240 #13245 #14130 #14137 #14138 #14017 Ghostty now transparently compresses scrollback that isn&#x27;t visible, reducing the physical memory those pages use by 70% to 90% for typical text-heavy history. Compression only runs while the terminal is idle and pages are decompressed on demand when you scroll back or search, so it has no measurable impact on I/O throughput. Thanks to compression, the default scrollback limit has been raised from 10 MB to 50 MB per terminal. On platforms that support compression, a full scrollback still generally uses less physical memory than the old 10 MB limit did. Note Compression lowers resident (physical) memory, not virtual memory, so look at resident memory when measuring it. It is currently available on macOS and 64-bit Linux. Beyond scrollback, memory usage is lower in many places: A new, empty terminal now uses about 16 KiB of terminal page memory on macOS, down from 128 KiB in Ghostty 1.3.1. On macOS and Linux, memory freed by clearing or trimming scrollback is now returned to the OS instead of being held until the terminal closes. Hidden tabs release their GPU resources. On macOS, with one visible tab and 20 hidden tabs, GPU memory dropped from about 385 MiB to 18 MiB. Rebuilding them when a tab becomes visible again takes under a millisecond. Performance Improvements PRs: #13209 #13220 #13226 #13227 #13537 #13827 #13587 #14011 #13722 #14035 #12760 There are performance improvements across the board in Ghostty 1.4 that yield significant gains compared to prior Ghostty versions. The biggest win came from a surprising discovery: on macOS, the kernel caps every read from a pty at about 1 KiB no matter how large the read buffer is. Previously, Ghostty processed each read as it arrived, so per-read overhead was paid every kilobyte, and the program writing output sat blocked while we parsed. Ghostty now drains the pty on one thread while parsing on another, raising end-to-end I/O throughput by 25% to 55% on macOS (M4 Max, plain and Unicode text) over Ghostty 1.3.x. VT processing itself is also much faster. In parser benchmarks, plain ASCII text went from 128 MB/s to 725 MB/s (5.7x), CJK text got 3.4x faster, and a 2.6 GB dataset of real-world terminal recordings from asciinema is processed about 25% faster. Together, these changes took cat -ing a 150 MB text file on macOS from 1.5 seconds to 566 milliseconds. Other notable improvements: Resize: resizing a terminal with a large scrollback is about 6x faster (120x80 with 10,000 lines of scrollback), and 3x to 5x faster with history full of CJK text or emoji. Rendering: the renderer holds the terminal lock 2.7x to 11x less per frame, leaving more time for the I/O thread during heavy output. Copy and search: formatting terminal contents as plain text, HTML, or VT, which backs clipboard copy, write_screen_file , and scrollback search, is 1.5x to 8x faster. Launch (macOS): about 15% faster from launch to visible window, and 27% faster to the first rendered frame. Idle energy: on macOS, the renderer&#x27;s display link now sleeps when there&#x27;s nothing to draw. On GTK, hidden tabs stop rendering, matching macOS. Large OSC sequences: OSC 52 clipboard payloads parse about 30x faster , and even short sequences like title changes are about 6x faster. New OpenGL Renderer (Linux, FreeBSD) PRs: #14052 #14269 The GTK app has a new rendering pipeline. It no longer uses GtkGLArea . Instead, the renderer draws with EGL on its own thread, exports each frame as a DMABUF, and hands it to GTK to display. Rendering is now triple-buffered, which should greatly reduce tearing, and no OpenGL calls run on the main thread anymore, which let us remove a number of workarounds. The most visible result is crisp text under fractional scaling. Text and box-drawing characters are no longer blurry with fractional display scaling such as 125% or 150% ( #1938 ). We fixed this once before, but it came back after upstream GTK changes. Ghostty now renders at the window&#x27;s true fractional scale, so every rendered pixel maps to exactly one pixel on screen. The new render surface needs a system EGL library (see Changes for Package Maintainers ). On GPU drivers that can&#x27;t export DMABUFs, Ghostty falls back to copying frames through the CPU, which is slower but works. Kitty Clipboard Protocol PRs: #13962 #13993 #13995 #13998 #14002 #14061 Ghostty now implements the Kitty clipboard protocol (OSC 5522) on both macOS and GTK. Ghostty 1.3 could parse the protocol but didn&#x27;t implement it. OSC 52 can only read and write plain text. The Kitty clipboard protocol lets programs running in the terminal read and write any kind of clipboard data, such as images or HTML, and lets them pick among the formats on the clipboard. Programs can also enable paste events (mode 5522), which tell the program what formats a paste contains so it can read the one it wants. This is how a terminal program can accept a pasted image, for example. Clipboard access follows the existing clipboard-read and clipboard-write configurations. By default, reads prompt for permission and writes are allowed. The permission prompt shows a preview of the clipboard contents, including images. Programs that send a password can have your answer remembered for the rest of that terminal session. A new clipboard-write-limit-bytes configuration limits the size of a single write (default 64 MiB). A write over the limit fails and leaves the clipboard untouched. Split Drag and Drop (GTK) PRs: #10423 #13706 You can now rearrange splits on GTK by dragging them, matching the macOS feature introduced in Ghostty 1.3. When a tab has two or more splits, each split shows a drag handle at the top. Grab the handle and drop the split onto any other split, including splits in other tabs and windows. An overlay shows which side of the target split it will land on. The terminal contents, working directory, and running processes all move with it. A new drag-handle configuration controls when drag handles are shown on both macOS and GTK: auto (default), always , or never . With never , splits can&#x27;t be rearranged with the mouse. Hiding the handles was a common request from users who found them in the way. On GTK, splits can only be dropped onto other splits. Dragging a split out to create a new tab or window is macOS-only. Terminal Emulation Accuracy PRs: #14454 #13494 #14483 #14538 #14673 #14375 #14144 Ghostty 1.4 includes dozens of improvements to core terminal emulation. We now run esctest , Thomas Dickey&#x27;s terminal conformance suite, against Ghostty&#x27;s terminal core in CI. Alongside that, we fixed many differences from xterm in cursor movement within margins, tab stops, character sets, mode reports, and more. You can find the full list of related changes in the terminal capabilities section. Ghostty also supports several new sequences, including soft terminal reset (DECSTR), extended cursor position reports (DECXCPR), backarrow key mode (DECBKM), and screen size reports in characters ( CSI 19 t ). Programs can also now ask whether the terminal is visible using visibility reports (mode 2033), so they can stop rendering while hidden. Keyboard encoding also matches xterm more closely, with fixes for modifyOtherKeys mode 2 and legacy Alt-as-Escape encoding of non-ASCII keys. Two new sequences are disabled by default because they can be abused by untrusted programs, including ones running on a remote machine: # Allow programs to resize the window (CSI 8 t) vt-window-resize-allowed = true # Allow programs to request screen checksums (DECRQCRA) vt-xt-checksum-report = true SSH Integration with ghostty +ssh PRs: #12582 #12814 #13533 #13844 #14472 #14854 Ghostty 1.2 introduced SSH shell integration features as a work in progress. In Ghostty 1.4, they&#x27;re backed by a new ghostty +ssh CLI action: a drop-in ssh wrapper that prepares the remote session for Ghostty and then runs the real ssh with your arguments forwarded unchanged. ghostty +ssh user@example.com # Or alias it so every ssh invocation goes through it alias ssh= &#x27;ghostty +ssh --&#x27; Before connecting, +ssh installs Ghostty&#x27;s terminfo on the remote host so the proper xterm-ghostty TERM value can be used, and forwards COLORTERM , TERM_PROGRAM , and TERM_PROGRAM_VERSION . If the terminfo install fails (for example, tic isn&#x27;t available on the remote), it falls back to TERM=xterm-256color . Flags such as --terminfo=false , --forward-env=false , and --verbose control each step. The ssh-env and ssh-terminfo shell integration features (still opt-in) now call +ssh too. Previously, each shell integration carried its own copy of this logic, which made up roughly a third of our shell integration scripts. Now bash, zsh, fish, elvish, and Nushell all behave identically, and you can get the same behavior from scripts or anywhere else by calling ghostty +ssh directly. The terminfo install itself is also more reliable. Ghostty now always installs its own bundled terminfo rather than accepting whatever xterm-ghostty entry the remote already has, and it reinstalls automatically when a Ghostty update changes the terminfo. It also no longer needs infocmp or Ghostty&#x27;s terminfo on the local machine. Installs are cached per host and port, so two machines behind one address no longer share a cache entry. And ssh-env no longer silently overrides SetEnv entries in your ~/.ssh/config ( #11518 ). The +ssh-cache command that manages this cache now takes positional destinations ( ghostty +ssh-cache user@example.com ) and has a new --prune=30d flag. See the breaking changes if you script against +ssh-cache . System Requirements macOS: The minimum required macOS version for Ghostty 1.4 remains unchanged (macOS 13 Ventura). Ghostty is now compatible with macOS 27. GTK: Ghostty 1.4 requires GTK 4.18 and libadwaita 1.7 , up from GTK 4.14 and libadwaita 1.5 in Ghostty 1.3. This aligns with our GTK/Adwaita version policy . Notably, Ubuntu 24.04 LTS doesn&#x27;t meet this requirement. Systems with older GTK or Adwaita versions can work around this requirement by using an older version of Ghostty or the Flatpak package. #14330 OpenGL (GTK): The minimum required OpenGL version remains 4.3, but Ghostty now renders through EGL instead of GTK&#x27;s OpenGL widget. This should be invisible for nearly everyone, but if Ghostty fails to start with an EGL error, please make sure your GPU driver provides a working EGL implementation. Important We previously announced that Ghostty 1.4 would require macOS 14. Nothing forced our hand to do this in this release, so we kept macOS 13 support. We still plan to drop macOS 13 in a future release. Apple dropped security support for macOS 13 in the fall of 2025, so we recommend upgrading regardless. Breaking Changes The following behaviors have changed in 1.4.0: copy-on-select has been reworked and now accepts none , primary , clipboard , or both . The meaning of clipboard has changed: it previously copied to both the selection clipboard and the system clipboard, and now copies only to the system clipboard. If you set copy-on-select = clipboard and want the old behavior, change it to both . #12600 #12604 macOS: copy-on-select now defaults to none (previously true ), so selecting text no longer copies it anywhere and middle-click paste of the selection no longer works by default. To restore the 1.3 behavior, set copy-on-select = primary . Note that an explicit copy-on-select = true on macOS now copies selections to the system clipboard, which is different from 1.3. #12600 #12604 macOS: cmd+arrow_up and cmd+arrow_down now run jump_to_prompt again, matching Terminal.app and Ghostty 1.2. In 1.3, these keys were hardcoded to scroll to the top and bottom and couldn&#x27;t be rebound. To keep the 1.3 behavior, set keybind = cmd+arrow_up=scroll_to_top and keybind = cmd+arrow_down=scroll_to_bottom . #12245 GTK: The default ctrl+shift+page_up and ctrl+shift+page_down keybinds now move the current tab left and right ( move_tab ), matching Firefox, GNOME Terminal, and VS Code. jump_to_prompt moved to ctrl+shift+arrow_up and ctrl+shift+arrow_down , so programs running in the terminal no longer receive those keys. If a program you use needs them, unbind them with keybind = ctrl+shift+arrow_up=unbind and keybind = ctrl+shift+arrow_down=unbind . #4998 #12458 Deprecations The list below contains deprecations that remain compatible today through a compatibility layer, but may break in a future release if they are ignored: scrollback-limit has been renamed to scrollback-limit-bytes , to make room for the new scrollback-limit-lines . #13473 copy-on-select = true is replaced with copy-on-select = primary on Linux and FreeBSD, or copy-on-select = clipboard on macOS. copy-on-select = false is replaced with copy-on-select = none . #12600 #12604 There is no set timeline to remove these deprecations, but we recommend adapting to the new configurations sooner rather than later to avoid any possible disruptions in the future.
